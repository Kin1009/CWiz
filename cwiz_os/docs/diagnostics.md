# Diagnostics design

## Entry and exits

- Entry: hold `SHIFT+7` during boot (`main.cwiz`).
- Exit: `AC` returns from the diagnostic menu to `main`, which halts. The
  diagnostics code never calls `app_launcher()`.

## Main screen

```
x+y=?                      correct/total
                           (both hex, wrap 00 after FF)
Press AC
```

- Operands and operator are generated from a RAM seed (`0xDCF2`).
- The result is always 1–5; `1`–`5` submit an answer.
- Correct: both counters increment (mod 256), `TEST OK` is centered on line 2,
  waits about one second, then halts.
- Wrong: only the total counter increments, no `TEST OK`, then halts.
- On entry, if `correct > total`, both counters are reset to 0.

## Option 6 — small-font menu

1. Display
2. Version & SUM
3. Key test
4. Clear RAM
AC: back

## Version & SUM

Four big-font lines:

1. Model: `EX-580` (580), `CW-880` (880), `CX-880` (880 PLUS).
2. `V.<A-Z>  <major>.<minor>.<build>` — the letter is `SUM % 26`; major/minor
   come from `build/version.cwiz`, the build number from the git commit count.
3. `SUM <hex> OK` or `SUM <hex> NG`.
4. `Press AC`; `SHIFT+AC` opens the serial screen.

## Serial

- Line 1: `[Serial number]` centered.
- Serial itself centered between lines 2 and 3; bytes at `DBE0..DBEB`.
- Format: `MMMBBBBBNNNN` (12 chars, no hyphens): 3-char model, 5-hex build,
  4-hex random.
- Line 4: `Press AC`.

## Boot integrity

`system.cwiz::init()` checks `DBD0..DBDF` for `0F..00`. On mismatch it writes
the pattern, calls `recover()` (wipe all RAM except `DBD0..DBDF`, with
`D000..D16B` last), then jumps to `0:A1CE`.

## SUM region

`SUM` adds every byte of:

- `menu_icons` (24 × 144 = 3,456 bytes)
- `_cw_font` (1,235 × 2 bytes, low then high)
- `_font` (760 bytes)

The expected value is generated by `tools/build_menu_bitmaps.py` and stored in
`menu_icons_sum`. Both sides read the same ROM tables, so the result is stable.

Do **not** use absolute `peek(addr)` over the packed ROM image for the
checksum: the CW target does not switch ROM banks for data reads, so addresses
outside the accessible window read RAM and the value changes on every boot.

## Display test

Automatic sequence, no keys required:

1. checkerboard
2. inverse checkerboard
3. all ink (`0xFF`)
4. all clear (`0x00`)

## Clear RAM

`SHIFT` confirms. The runtime `wipe` builtin clears `0xD000..0xFFFF` using
registers only and then halts, so the active stack does not interrupt the wipe.
