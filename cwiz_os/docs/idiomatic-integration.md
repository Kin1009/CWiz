# Idiomatic CWiz integration into the custom OS

This is the proper-port record for wiring the converted idiomatic modules from
`firmware-re/fx580/cwiz/idiomatic/{bank0,bank1a,bank1b,bank2,bank3key}/` into
the real `cwiz_os` custom ROM.  It complements `docs/integrated-packager.md`;
that document still describes the unmodified single-blob build.  Here the
packager is **not** changed — only its `--blob` input is a concatenation of two
independently compiled images, generated by the Makefile.

## 1. What actually runs in the boot payload

`apps/recovered/recovered.cwiz` (reached with **SHIFT+8**; SHIFT+7 still enters
diagnostics first) now calls these idiomatic modules directly:

| call on screen | function | source module | ROM id | equivalence evidence (recorded, not assumed) |
|---|---|---|---|---|
| `KEY` | `scan_raw_keycode()` | `cwiz/idiomatic/bank3key/key_getkeycode.cwiz` | `f_2F5E8` | `analysis/idiomatic_b3key.json` → converted, plus §5.3 dynamic key primitives: **154/154 cases** match an independent Python SFR keyboard model (56 scan positions + 2 no-press/stuck-key, 20 debounce, 20 held, 56 map). The 7-column KO/KI scan is the real non-blocking matrix read. |
| `RAW` (two bytes) | same call's output buffer | as above | `f_2F5E8` | `byte 0 = ~F040`, `byte 1 = F046` strobe; the same evidence covers both bytes. |
| `DSP` | `display_helper_17094()` | `cwiz/idiomatic/bank1a/display_helper_17094.cwiz` | `f_17094` | Module header: "returns the same 0x0007 constant as R0"; `analysis/idiomatic_b1a.json` static check `pass` (constants/calls/memory). |
| (internal) | `zero_key_lines()` | `cwiz/idiomatic/bank3key/key_runtime.cwiz`, pulled in by `key_getkeycode.cwiz` | `f_0A16A` | `docs/idiomatic-b0.md` runtime harness **PASS**: `F046 = 0`, with a deliberately wrong negative control producing a B-to-self halt. |

The UI still uses only `clearRender()` / `clear()` / `print_cw()` / `num_cw()` /
`render()`, and the boot-chord drain/wait/return-to-launcher pattern is
unchanged.  `store_serial_number`, `app_launcher`, `diagnostic_menu` and
`clean_ram`/`wipe()` are untouched; diagnostics remains the first authority.

### What was deliberately *not* swapped in

* **`display_metrics_table_lookup()` (`f_09E24`) has no idiomatic port.**
  `analysis/idiomatic_b0.json` records it as `status: blocked`,
  `blocker: software-stack`, `blocker_text: "table lookup through FP-relative
  mode slots"`.  No module exists in any of the five batches.  Rather than
  silently substitute an unrelated function under the old `METRIC` label, the
  row was relabelled `DSP` and is driven by the independently verified
  `display_helper_17094()` leaf.  The structural recovery
  (`cwiz/deep/unknownA/fw_09E24.cwiz`) is still preserved in the blob.
* `b2_capture_key_code` (`cwiz/idiomatic/bank2/b2_capture_key_code.cwiz`) is a
  like-for-like idiomatic replacement for the old inline `capture_key_code`,
  but its ledger entry (`analysis/idiomatic_b2.json`) is
  `equivalence.status: structural` (0 execution vectors), and it includes
  `cwiz/linked/key_ports.cwiz`.  The bank-3 `scan_raw_keycode` has strictly
  stronger evidence and no structural dependency, so it was chosen instead.
* `key_getscancode.cwiz` was **not** used: its context is a full
  display/timer-path model whose cross-module calls go through `call_*` shims
  in `key_runtime.cwiz` that return `0` (`docs/idiomatic-b3key.md` §6).  Using
  it in the OS would silently lose the scan.  This is a real blocker, not an
  omission.
* The BCD / `memzero` / `clear_screen_buffer` conversions
  (`byte_to_packed_bcd` — exhaustive 256/256; `memzero`,
  `clear_screen_buffer` — bank-0 runtime PASS) cannot fit in the remaining
  8 bytes of the boot overlay.  They are preserved in the idiomatic blob
  (see §3) and documented here rather than dropped.

## 2. Overflow: why the boot payload cannot hold more

The stock key map starts at `0:7B0E`, so the boot program is hard-capped at
**31,502 bytes**.  Replacing the old inline structural modules
(`_linked_api`, `key_ports`, `key_capture`, `fw_09E24` — about 680 B) with the
two idiomatic modules above leaves only a few hundred bytes.  The final build:

```
Payload budget: 31494 / 31502 bytes (0x7B06 / 0x7B0E), 8 bytes free
```

The 8-byte margin absorbs the ±2-byte variation caused by the regenerated
serial-number constants.  `make integrated` runs `check_budget()` on every
build and `make verify-integrated` re-checks it.  No other cwiz_os file was
trimmed to make room.

## 3. Blob manifest (exact bytes passed to the unmodified packager)

`tools/package_integrated.py` accepts one `--blob`.  The Makefile compiles two
images at origin 0 and concatenates them in a fixed order:

| offset in `--blob` | linear ROM offset | size | content |
|---:|---:|---:|---|
| `0x00000` | `0x30E40` (`3:0E40`) | 30,840 B | `recovered-blob.bin`: shim guard + **all** `cwiz/linked/**` and `cwiz/deep/**` modules (unchanged from `make blob-source`) |
| `0x07878` | `0x386B8` (`3:86B8`) | 23,664 B | `idiomatic-blob.bin`: curated idiomatic module set (see below) |
| — | `0x3E328` | — | end of combined blob; 7,320 B of the bank-3 gap remain free |

The 23,664-byte idiomatic image is 208 includes generated by the new
`make idiomatic-blob-source` target:

| batch | modules in the blob | note |
|---|---|---|
| `bank0` | 59 | every module except `lcd_reset_writes`, `memzero`, `update_screen_mode`, `zero_answer_block`, `zero_history_and_build_digit` (pulled in by parents) and the three `#pragma once` headers. These modules do not have `#pragma once`, so listing them twice is a compile error. |
| `bank1a` | 70 | all emitted modules |
| `bank1b` | 44 | 43 emitted modules + `_b1b_common.cwiz` |
| `bank2` | 35 | maximal conflict-free subset; see below |
| `bank3key` | 0 | its core scan is inline; `key_runtime.cwiz` redefines bank-0's SFR leaves, so it cannot share this translation unit |

`bank2` modules each carry their own boundary-stub definitions (`b2_delay`,
`b2_line_print`, `b2_diag_print_version`, …), so only 35 of the 53 converted
modules can be co-compiled.  `b2_capture_key_code` is additionally excluded
because it includes `linked/key_ports.cwiz`, whose `zero_key_lines` /
`drive_all_key_lines` collide with the bank-0 and bank-3 key leaves.  The exact
35 names are the `B2_IDIOMATIC` list in the Makefile; `excl='$(B0_EXCLUDE)'`
documents the five bank-0 roots omitted from the blob.

Both images are compiled with `wizc --target cw --lang cwiz` at origin 0.  The
packager writes them verbatim into the measured erased bank-3 gap, checks that
no protected stock region or the checksum word is touched, recomputes the
fx-580 checksum, and verifies the bytes afterwards.  No packager source was
edited.

### Blob relocation blocker (honest)

The blob is a **preserved code artifact, not an in-place executable image** —
this was already true for the linked/deep blob and is unchanged for the
idiomatic one.  The compiler emits 16-bit absolute code addresses (BL/B) and
ROM data references that assume origin 0 and `DSR = 0`.  Relocating to
`3:0E40` without a bank-aware loader/relocation step would not execute
correctly.  There is a `tools/relocate_blob.py` / `tools/verify_blob_relocation.py`
experiment elsewhere in `cwiz_os/tools` owned by another agent; this build
does **not** invoke them.  Only the small subset compiled into the boot
payload is actually called.  A second blocker recorded by the conversion
agent is `var_base = 0xD000` collision: several bank-3key modules model
globals at `0xD000..0xD1FF`, which overlaps the CWiz allocator
(`docs/idiomatic-b3key.md` §5.4); the chosen `scan_raw_keycode` uses only
locals and SFRs, so it is safe.

## 6. Emulator evidence (`build/idiomatic-evidence/`)

All three runs used the **same** ROM SHA-256 and the integrated model dir;
`run_mode: run`, `ok: true` in every report.

| screenshot | chord | final PC | what is visible |
|---|---|---:|---|
| `boot.png` | none | 31018 (`0x791A`) | launcher, "1:Calculate" menu — unchanged |
| `recovered.png` | SHIFT+8 (`casioctl key hold F1` + `8`) | 31016 (`0x7918`) | `REC` / `KEY 1` / `RAW 12B 1` / `DSP 7` — the `KEY`/`RAW` bytes come from the idiomatic `scan_raw_keycode()` matrix scan, `DSP 7` from idiomatic `display_helper_17094()` |
| `diagnostics.png` | SHIFT+7 (`casioctl key hold F1` + `7`) | 30930 (`0x78D2`) | `4+1=?  00/00`, `Press AC` — diagnostics still wins the first-authority check |

The payload assembly (`build/cwiz-os-program.asm`) confirms the real call
sites: `BL f_scan_raw_keycode` and `BL f_display_helper_17094` in
`recovered_app`, with `f_scan_raw_keycode` containing the 7-column loop and
`BL f_zero_key_lines`.  (`key_runtime.cwiz`'s unused `call_scan_raw_keycode`
shim is still emitted as dead code; it is never called by this app.)

The `RAW` value `12B / 1` is the live matrix state while the SHIFT+8 chord is
held: byte 0 is the inverted KI row mask, byte 1 is the KO column strobe
`0x01`, exactly the format documented in `key_getkeycode.cwiz`.

```python
#!/usr/bin/env python3
import json, shutil, sys, time

for tag, key in (("recovered", "8"), ("diagnostics", "7")):
    with er.Emulator(app, ctl, WORK, tag, MODEL, timeout=20.0) as emu:
        emu.ctl.text("reset")
        emu.ctl.text("key", "hold", "F1", "10000")
        emu.ctl.text("key", "hold", key, "10000")
        emu.ctl.text("resume")
        time.sleep(2.5)
        shot = emu.screenshot(tag)
        shutil.copy2(shot["path"], EVIDENCE / f"{tag}.png")
    print(tag, shot["path"])
```

## 8. Summary of blockers

1. `f_09E24` (the old `METRIC` source) is blocked upstream — no idiomatic port
   exists; its UI row was honestly relabelled rather than faked.
2. Only 8 bytes of boot payload remain.  The verified BCD, `memzero`,
   `clear_screen_buffer` and bank-2 key helpers are preserved in the blob but
   are not callable from the OS.
3. The blob is not relocatable/executable in place; no bank-aware loader exists
   in this build, and the packager is deliberately unchanged.
4. `bank3key`'s higher-level functions use returning-`0` call shims and
   `0xD000..0xD1FF` globals; only its leaf `scan_raw_keycode` was safe to port
   inline.
5. `bank2`'s per-module boundary stubs and `b2_capture_key_code`'s
   `linked/key_ports.cwiz` dependency limit the co-compilable blob subset to
   35 modules.  Editing those conversion files was outside this task's
   ownership.
